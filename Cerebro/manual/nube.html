      Capítulo 6

      La nube de Claude Code

      Cuando usas Claude Code desde la web, la app de escritorio o el teléfono, el agente no trabaja en tu computador: trabaja en una máquina temporal en la nube. Entender eso explica por qué todo tiene que terminar en GitHub.

      Qué es una sesión en la nube

      Cada sesión recibe una máquina virtual nueva: un computador prestado, con Ubuntu 24.04, unos 4 procesadores, 16 GB de memoria y 30 GB de disco (límites aproximados que pueden cambiar). En esa máquina se clona tu repositorio, Claude trabaja y, al final, sube los cambios a GitHub.

      Por qué GitHub es el disco duro del cerebro

      1. La máquina es temporal. Cada sesión empieza con un repositorio recién clonado y la máquina se recupera después. GitHub es lo único que permanece.
      2. Las sesiones no comparten disco. Una sesión nueva no ve lo que otra dejó a medias: solo ve lo que está en GitHub.
      3. Revisas antes de aceptar. El agente sube a una rama y abre un pull request; tú decides si entra en main.
      4. Tus credenciales quedan fuera. Un proxy de GitHub pone tus permisos reales por fuera de la máquina; dentro solo hay una credencial limitada.

      Regla práctica

      Si algo importante solo está en el chat o en la máquina, no existe todavía. Pide siempre: «haz commit y push».

      Qué es un entorno en la nube

      Un entorno es la configuración guardada con la que arrancan las sesiones: qué sitios de internet pueden visitar, qué claves pueden usar sin verlas, qué se instala al empezar y qué variables se definen. Lo eliges en el selector que está debajo del cuadro de mensaje al empezar una sesión. Tienes dos:

      Un entorno tiene cuatro piezas:

      1 · Acceso a la red

      Decide a qué sitios de internet puede conectarse la máquina. Hay cuatro niveles:

      NivelQué permiteCuándo usarlo
      NingunoSin salida a internet desde la máquinaTrabajo con información muy sensible
      De confianza (Trusted)Solo una lista de sitios conocidos: registros de paquetes, GitHub, herramientas de la nubeProgramar sin necesidad de navegar
      Completo (Full)Cualquier sitioInvestigación web abierta, como la de este proyecto
      Personalizado (Custom)Tu propia lista de dominios, con o sin la lista por defectoCuando solo necesitas unos pocos sitios concretos
      # Ejemplo de dominios permitidos en el nivel Personalizado (uno por línea)
api.ejemplo.com
*.ejemplo.com

      Algunas cosas funcionan con cualquier nivel: GitHub (por su propio proxy), los conectores de Claude que actives (como Gmail o Google Drive, que pasan por los servidores de Anthropic) y los sitios que tengan un secreto de red guardado.

      2 · Secretos de red

      Un secreto de red es una clave de API o un token que guardas en el entorno para que Claude pueda usar un servicio sin ver nunca la clave. Cuando una petición sale de la máquina hacia el sitio indicado, el proxy de Anthropic le añade la clave por fuera.

      • Se añaden en el entorno, en la sección Network secrets, de uno en uno, indicando el sitio y la clave.
      • Después de guardarla, la clave no se puede volver a ver.
      • Nunca se envía a GitHub, a la API de Anthropic, a los registros públicos de paquetes ni durante el script de configuración.
      • Nunca pegues una clave en el chat. Si el agente necesita una, te mostrará un formulario seguro para guardarla.

      3 · Script de configuración

      Un pequeño programa (en Bash) que se ejecuta al empezar una sesión nueva, antes de que arranque Claude, con permisos de administrador. Sirve para instalar herramientas que la máquina no trae.

      #!/bin/bash
# Ejemplo: instalar un programa que no viene instalado
apt update && apt install -y shellcheck
      • Debe terminar sin errores; si falla, la sesión no arranca bien.
      • Debe tardar menos de unos 5 minutos: así Anthropic guarda una foto de la máquina ya preparada y las siguientes sesiones arrancan rápido. Esa foto se renueva cuando cambias el script o la red, o a los 7 días aproximadamente.
      • No puede leer las variables ni los secretos del entorno.

      El cerebro de Arvyon solo usa Python, que ya viene instalado, así que no necesita script.

      4 · Variables de entorno

      Valores de configuración que cualquier comando de la sesión puede leer. Se escriben con el formato NOMBRE=valor, una por línea.

      NIVEL_LOG=detallado
ZONA_HORARIA=America/Bogota

      No son para claves

      Cualquiera que use el entorno puede leer las variables. Para claves y contraseñas se usan los secretos de red.

      Si cambias una variable, una sesión que ya está abierta la verá cuando su máquina se reanude o se reconstruya; una sesión nueva la ve desde el principio.

      Dónde se cambia

      1. Al empezar una sesión nueva: el primer control debajo del cuadro de mensaje abre el selector de entornos. Pasa el cursor sobre Arvyon y pulsa el icono de ajustes.
      2. En una sesión abierta: pulsa la flecha junto al título de la sesión y elige Edit cloud environment.
      3. En el diálogo verás Network access, Setup script, Environment variables y Network secrets. Guarda con Save changes.

      El agente también puede proponerte cambios en el entorno, pero siempre aparece una tarjeta para que tú los apruebes.

      Recomendación para Arvyon

      Hoy está bien así

      El acceso completo es práctico para la investigación web de la Fase 1, y el entorno no guarda claves, así que hay poco que proteger.

      Cuándo revisarlo

      Si un día guardas un secreto de red (por ejemplo, la clave de un CRM o de WhatsApp para una demo), considera pasar a Personalizado con solo los sitios necesarios. Así, aunque el agente lea una página web con instrucciones maliciosas, no podrá enviar información a cualquier sitio.
